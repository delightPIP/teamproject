# `/adr` — 아키텍처 및 기술 의사결정 기록(ADR) 스킬

기술 스택, 라이브러리, 데이터 저장 방식 등 **대안이 여러 개 있고 그중 하나를 골라야 할 때** 비교 과정과 채택 이유를 `docs/adr/`에 기록으로 남깁니다. (필수 파이프라인 외에 큰 결정이 필요할 때만 선택적으로 호출)

## 실행 절차

### 1. 결정 안건 확인
- 사용자가 입력한 기술 고민을 파악합니다 (예: `/adr 상태관리 도구 선택`, `/adr 크롤링 엔진 비교`).

### 2. 3대 대안 비교 분석
- 고려한 후보 2~3가지를 나열하고 각각의 장단점을 정리합니다.
- 우리 프로젝트(시간제한, 난이도, 성능) 관점에서 최종 선택된 안과 기각된 안의 이유를 정리합니다.

### 3. `docs/adr/` 기록 저장
`docs/adr/0001-[안건명].md` 파일로 저장합니다:

```markdown
# ADR [번호]: [결정 제목]

- **상태**: 채택됨 (Accepted)
- **결정 일자**: YYYY-MM-DD
- **참여 팀원**: 전원

## 1. 배경 및 문제 상황
- 어떤 문제를 해결하기 위해 이 기술 선택이 필요했는가?

## 2. 고려한 대안들
| 후보 | 장점 | 단점 / 채택하지 않은 이유 |
| :--- | :--- | :--- |

## 3. 최종 결정 및 채택 이유

- 주의할 점:
```

> "✅ `docs/adr/`에 기술 의사결정 기록이 저장되었습니다."
