# `/toissue` — 작업 이슈(Issue) 분할 스킬

`docs/SPEC.md`와 `docs/POLICY.md`를 분석하여, 팀원들이 겹치지 않고 병렬로 작업할 수 있도록 **작업 단위(기능별) 이슈 티켓**을 분할 생성합니다.

## 실행 절차

### 1. `docs/SPEC.md` 기반 기능 단위 분해
- 스펙 문서를 읽고, 병렬로 작업할 수 있는 3~5개의 독립 기능 단위로 작업을 나눕니다.
- 기계적인 제약 대신, **각 이슈가 주로 다룰 핵심 모듈/파일을 지정하여 작업 간 충돌을 최소화**합니다.

### 2. 이슈 목록 출력 및 저장
GitHub Issues에 등록하거나 바로 복사해 쓸 수 있도록 정형화된 이슈 티켓 목록을 출력하고, 필요 시 `docs/ISSUES.md`에 기록합니다:

```markdown
# 📋 이번 스프린트 작업 이슈 목록

### Issue #1: [뼈대] 기본 레이아웃 및 진입점 구성
- **작업 내용**: 기본 HTML/컴포넌트 뼈대 구조 세팅 및 공통 스타일 적용
- **주요 파일**: `index.html`, `style.css` (또는 프레임워크 엔트리)
- **완료 조건**:
  - [ ] 상단 필터바와 메인 그리드 컨테이너가 화면에 표시됨
  - [ ] 모바일 뷰에서도 가로 스크롤 없이 반응형으로 표시됨

### Issue #2: [데이터] 데이터 로드 및 필터/정렬 로직 구현
- **작업 내용**: 데이터 소스(API/JSON)를 불러오고, `POLICY` 규칙에 따른 필터링 및 할인율 계산 로직 작성
- **주요 파일**: `src/data.js` 또는 `src/api.py`
- **완료 조건**:
  - [ ] 브랜드 및 행사 유형별 필터링 함수가 정상 동작함
  - [ ] 정책에 정의된 계산 공식대로 할인율이 산출됨

### Issue #3: [컴포넌트] 카드 렌더링 및 UI 배지 표시
- **작업 내용**: 데이터 객체를 받아 개별 상품/항목 카드를 렌더링하고 시각적 배지 부착
- **주요 파일**: `src/card.js` 또는 컴포넌트 파일
- **완료 조건**:
  - [ ] 정가, 할인가, 할인율 배지가 카드에 올바르게 노출됨
  - [ ] 가격 누락 시 정책에 따른 대체 문구('가격 문의' 등)가 표시됨

### Issue #4: [예외 처리] 데이터 장애 대응 및 Fallback UI
- **작업 내용**: `POLICY` 3번 예외 정책 구현 (API 오류, 데이터 0건 시 대체 화면)
- **주요 파일**: `src/error.js` 또는 상태 처리 로직
- **완료 조건**:
  - [ ] 데이터 호출 실패 시 화면 전체 중단 없이 에러 배너와 직전 캐시 데이터가 유지됨
  - [ ] 결과가 0건일 때 친절한 안내 문구가 표시됨
```

### 3. 작업 분담 및 다음 단계 안내
- 팀원들이 본인이 맡을 이슈를 하나씩 픽(Assign)하도록 안내합니다:
> "✅ 이슈 분할이 완료되었습니다. 각자 맡을 이슈를 정한 뒤, 터미널에서 브랜치를 생성하고 **/impl #이슈번호**를 실행해 구현을 시작하세요!"
> 
> ```bash
> git checkout main && git pull origin main
> git checkout -b feat/#이슈번호-작업명
> ```
