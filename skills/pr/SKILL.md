# `/pr` — PR 검증 및 템플릿 생성 스킬

작업을 마치고 원격 저장소에 PR(Pull Request)을 올리기 전, **Git 충돌을 원천 차단하기 위해 `origin/main` 리베이스 여부를 점검**하고 팀원이 즉시 리뷰할 수 있는 PR 템플릿을 생성합니다.

## 실행 절차

### 1. Rebase 사전 검증 (충돌 방지 핵심)
현재 Git 상태를 검사하여 로컬 브랜치가 `origin/main`의 최신 커밋을 반영하고 있는지 확인합니다:

1. **최신 상태 확인**:
   ```bash
   git fetch origin
   ```
2. **리베이스 필요 시 가이드**:
   - ⚠️ 만약 로컬 브랜치가 `origin/main`보다 뒤처져 있다면, 즉시 경고하고 리베이스 명령어를 안내합니다:
     ```bash
     git rebase origin/main
     ```
   - *충돌 발생 시*: 충돌 파일 수정 후 `git add <파일>` ➔ `git rebase --continue` 가이드.
3. **푸시 가이드**:
   - 리베이스가 완료되었으면 원격 브랜치로 푸시 안내:
     ```bash
     git push origin <현재브랜치명>
     ```

### 2. PR 제목 및 본문 템플릿 생성
GitHub PR 작성창에 바로 붙여넣을 수 있도록 카르마 컨벤션 제목과 마크다운 템플릿을 출력합니다:

- **PR 제목 추천**: `<type>(<scope>): 작업 내용 요약 (#이슈번호)`  
  *(예: `feat(filter): 편의점 행사 유형별 필터링 기능 추가 (#2)`)*

```markdown
## 📌 관련 이슈
- Closes #[이슈번호]

## 🛠️ 작업 내용
- [x] 
- [x] 

## ⚖️ 정책(POLICY) 및 스펙(SPEC) 준수 확인
- [x] 비밀키/민감정보가 코드에 노출되지 않았음을 확인했습니다.
- [x] `docs/POLICY.md`의 규칙(계산 공식, 예외 처리)을 준수했습니다.
- [x] `origin/main`을 기준으로 로컬 리베이스(rebase)를 완료했습니다.
- [x] 커밋 메시지가 카르마 컨벤션 규칙을 준수하고 있습니다.

## 📸 테스트 및 확인 방법
- [화면 캡처 또는 동작 확인 방법 1~2줄]

## 👥 리뷰어 안내
- 작성자 외 팀원 1명 이상의 Approve(승인) 후 머지해 주세요!
```
