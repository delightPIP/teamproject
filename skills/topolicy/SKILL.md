# `/topolicy` — 정책(Policy) 및 엣지 케이스 정의 스킬

`docs/PRD.md`를 분석하여 개발 도중 코드를 뒤엎지 않도록 **서비스 규칙, 제약조건, 예외 처리 정책**을 도출하고 `docs/POLICY.md`로 정리합니다.

## 실행 절차

### 1. `docs/PRD.md` 분석 및 정책 질문 도출
먼저 `docs/PRD.md`를 읽고, 프로젝트 특성에 맞춰 다음 3대 영역에서 결정을 내려야 할 질문을 선별하여 사용자에게 던집니다:

1. **보안 및 데이터 규칙**:
   - API 키나 비밀정보를 프론트엔드/레포에 노출하지 않는 방법은? (예: `.env` 필수, 브라우저 직접 호출 금지 등)
   - 데이터 수집 시 지켜야 할 제한은? (예: 요청 간 1초 쉬기, 캐시 적용 등)
2. **비즈니스 계산 및 판정 기준**:
   - 데이터 계산 공식은 무엇인가? (예: 1+1 상품의 할인율 = 50%, 정가가 없으면 어떻게 표시하는가?)
   - 분류/필터 기준은 무엇인가? (예: 시간대 구분 기준 시각, 카테고리 매핑 규칙)
3. **예외 및 장애 대응 (Fallback)**:
   - 외부 API가 죽거나 429/403 응답을 줄 때 화면을 어떻게 처리할 것인가? (예: 에러 배너 노출, 이전 캐시 데이터 유지 등)
   - 검색 결과나 데이터가 0건일 때의 동작은?

### 2. `docs/POLICY.md` 작성 및 저장
사용자/팀의 결정을 반영하여 `docs/POLICY.md`를 생성합니다:

```markdown
# ⚖️ 서비스 및 기술 정책 (POLICY)

## 1. 보안 및 데이터 거버넌스 정책
- **비밀키 취급**: API 키 등 민감 정보는 `.env`에서만 관리하며 레포지토리에 절대 커밋하지 않는다.
- **요청 및 캐싱**: 무분별한 재호출 방지를 위해 최소 [N]분 단위의 캐시를 적용한다.

## 2. 비즈니스 규칙 및 계산 공식
- **[항목 1] 판정/계산 기준**:
  - 규칙 A: 
  - 규칙 B: 
- **데이터 정제 규칙**:
  - 누락된 값(Null/NaN)은 [대체 표기]로 처리한다.

## 3. 예외 상황 및 장애 대응 정책 (Edge Cases)
- **외부 데이터 로드 실패 시**: 전체 화면을 중단하지 않고 [에러 배너 / 직전 캐시 데이터]를 노출한다.
- **데이터 0건일 때**: [친절한 안내 문구]를 표시한다.
- **경계값 처리**: [극단적인 수치나 이상값]은 [특수 플래그/표시]를 부여한다.
```

### 3. 완료 안내
생성된 정책의 핵심 3가지를 요약하고 다음 단계를 안내합니다:
> "✅ `docs/POLICY.md`가 생성되었습니다. 이제 화면 레이아웃과 구체적인 구현 스펙을 잡기 위해 **/tospec**을 실행하세요."
