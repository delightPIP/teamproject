# `/toPolicy` — 정책(Policy) 및 엣지 케이스 정의 스킬

`docs/PRD.md`를 분석하여 개발 도중 코드를 뒤엎지 않도록 **서비스 규칙, 제약조건, 예외 처리 정책 초안을 즉시 제시**하고, 팀원의 1턴 확인을 거쳐 `docs/POLICY.md`로 저장합니다.

## 실행 절차 (초안 선제시 & 1턴 확인)

### 1. 정책 초안 즉시 생성 및 화면 제시
`docs/PRD.md`를 읽고 빈 질문을 던지는 대신, AI가 프로젝트에 맞는 **합리적인 기본 정책 초안을 먼저 작성하여 화면에 출력**합니다:

1. **보안 및 데이터 규칙 초안**: API 키 금고(`.env`) 규칙, 호출 딜레이 및 캐싱 기준
2. **비즈니스 규칙 초안**: 할인율/점수 계산 공식, 정가 누락 시 처리 기준 등
3. **예외 및 장애 대응 초안**: 데이터 로드 실패(429/403) 시 Fallback 배너, 데이터 0건 시 안내 문구

### 2. 1턴 확인 및 저장
초안을 보여준 뒤, 사용자/팀에게 딱 1번 확인 질문을 던집니다:
> *"위 정책 초안에서 계산 공식이나 예외 처리 기준을 이대로 저장할까요, 아니면 수정할 부분이 있나요?"*

- **사용자가 "좋아/그대로 가/저장해"라고 하거나 이견이 없을 때**: 초안 그대로 `docs/POLICY.md` 파일 생성
- **사용자가 특정 규칙 수정을 요청할 때**: 해당 내용을 즉시 반영하여 `docs/POLICY.md` 파일 생성

### 3. 산출물 구조 (`docs/POLICY.md`)
```markdown
# ⚖️ 서비스 및 기술 정책 (POLICY)

## 1. 보안 및 데이터 거버넌스 정책
- **비밀키 취급**: API 키 등 민감 정보는 `.env`에서만 관리하며 레포지토리에 절대 커밋하지 않는다.
- **요청 및 캐싱**: 무분별한 재호출 방지를 위해 최소 [N]분 단위의 캐시를 적용한다.

## 2. 비즈니스 규칙 및 계산 공식
- **[항목 1] 판정/계산 기준**:
  - 규칙 A: 
  - 규칙 B: 
- **데이터 정제 규칙**:
  - 누락된 값(Null/NaN)은 [대체 표기]로 처리한다.

## 3. 예외 상황 및 장애 대응 정책 (Edge Cases)
- **외부 데이터 로드 실패 시**: 전체 화면을 중단하지 않고 [에러 배너 / 직전 캐시 데이터]를 노출한다.
- **데이터 0건일 때**: [친절한 안내 문구]를 표시한다.
- **경계값 처리**: [극단적인 수치나 이상값]은 [특수 플래그/표시]를 부여한다.
```
