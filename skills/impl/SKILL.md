# `/impl` — 이슈 기반 구현 및 정책 검증 스킬

팀원이 배정받은 이슈를 구현할 때, **`docs/POLICY.md`의 규칙과 `docs/SPEC.md`의 설계를 자동으로 주입**받아 오차 없이 코드를 작성하고 자체 검증합니다.

## 실행 절차

### 1. 사전 검사 (Pre-flight Check)
- 작업자가 인자로 전달한 이슈를 확인합니다 (예: `/impl #2` 또는 `/impl #2 필터링 로직`).
- 현재 Git 브랜치를 확인합니다:
  - ⚠️ 만약 `main` 브랜치에 있다면, 즉시 경고하고 작업 브랜치 생성을 안내합니다:
    ```bash
    git checkout main && git pull origin main
    git checkout -b feat/#이슈번호-작업명
    ```

### 2. 컨텍스트 자동 로딩
- `docs/POLICY.md`와 `docs/SPEC.md`를 메모리에 로드하여 다음 사항을 파악합니다:
  - **지켜야 할 정책**: 계산 공식, 예외 처리 규칙, 보안 수칙(키 노출 금지)
  - **구현해야 할 스펙**: 데이터 스키마, 컴포넌트 명칭, 함수 입력/출력 규격
- ⚡ **POLICY / SPEC이 없는 경우 (빠른 개발 모드)**: 두 문서가 생략되어 없더라도 `docs/PRD.md`와 해당 GitHub 이슈 본문의 작업 내용, 담당 파일, 완료 조건을 최우선 컨텍스트로 삼아 문제없이 구현을 진행합니다.

### 3. 단계별 코드 구현
- 해당 이슈의 완료 조건을 충족하도록 코드를 작성하거나 수정합니다.
- 불필요하게 다른 팀원의 작업 영역이나 공통 설정을 임의로 변경하지 않고, 이슈에 관련된 파일에 집중합니다.

### 4. 자체 정책 검증 (Self-Verification Checklist)
코드를 작성한 후, AI가 다음 체크리스트를 점검하여 결과를 보고합니다:
- [ ] **보안 점검**: 코드 내에 하드코딩된 API 키나 비밀 토큰이 없는가?
- [ ] **정책/요구사항 준수**: `docs/POLICY.md`(또는 `docs/PRD.md` 및 이슈 본문)의 규칙과 요구사항이 코드에 반영되었는가?
- [ ] **스펙/조건 일치**: `docs/SPEC.md`(또는 이슈 본문의 완료 조건 체크리스트)에 정의된 구조와 조건을 충족하는가?

### 5. 커밋 가이드 (카르마 컨벤션 & 1 Action 1 Commit)
- **1 Action = 1 Commit 원칙**: 여러 기능이나 변경점을 한 번에 묶지 않고, 하나의 논리적 동작/수정 단위마다 개별 커밋합니다.
- 검증이 완료되면 **카르마 컨벤션(`<type>(<scope>): <subject>`)**을 준수하는 커밋 명령어를 제안합니다:
  ```bash
  git add <작업파일>
  git commit -m "feat(도메인/모듈): 작업 내용 요약 (#이슈번호)"
  ```
  *타입 기준*: `feat`(기능 추가), `fix`(버그 수정), `docs`(문서), `style`(포맷팅), `refactor`(리팩토링), `test`(테스트), `chore`(설정/환경)
