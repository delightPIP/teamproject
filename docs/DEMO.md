## 1. 데모 시나리오 (PRD 4장 유저 저니, 8분)

데모는 PRD 4장의 저니를 그대로 따라간다. 발표자는 PO, 화면 조작도 PO가 한다. 개발자는 질문을 받는다.

#### 발표 당일 아침 순서 (2026-11-11 PO 추가)

재발견은 **정확히 7·14·30일 전** 별이 있어야 뜬다(POLICY 2-2). 시드 스크립트(`apps/server/vault/seed.ts`)는 **실행한 시각 기준**으로 7일 전 별을 만든다. 그래서 11/11에 넣은 시드로 11/12에 발표하면 그 별이 8일 전이 되어 **재발견이 뜨지 않는다.** 수집 앱은 재발견 알림을 **하루 1번**만 보내고, 그 날짜를 `settings.json`의 `lastNotifiedLocalDate`에 적는다. 알림 시각이 지난 뒤 확인했을 때 보관함에 후보가 없어도 "오늘은 보냄"으로 적는다(`apps/collector/main/notifier.ts`, 1분마다 확인).

**이 순서의 전제**
- **실서버**로 보여 줄 때만 해당한다. 가짜 서버(위 "서버" 줄)는 보관함을 쓰지 않아 재발견 후보가 없다. 그때 데모 4~5분은 생략하고 "재발견은 실서버에서 동작합니다"라고 말한다.
- 시드는 **주 화면 PC 1대**에만 넣는다(위 "데모 PC" 줄).
- 수집 앱은 **개발 모드(`npm start`)** 로 띄운다. main에는 수집 앱 패키징 설정이 없어(2026-11-11 확인, `spikes/electron`에만 있음) 설치본이 없다. 그래서 아래 2장 AC-재발견-2와 4장 "패키징된 앱" 항목의 설치본 확인은 이번 발표에 해당하지 않는다. 알림 시각 환경 변수 `SPACELOG_NOTIFY_AT`은 개발 모드에서만 읽힌다(`settingsStore.ts`). 설치본으로 바꾸면 이 변수는 무시되고, 앱을 끈 상태에서 `settings.json`의 `notificationTime`을 고쳐야 한다.
- ⚠ **개발 모드라 알림 클릭이 안 될 수 있다.** ADR 0001 스파이크에서는 윈도우 개발 모드 알림 클릭 콜백이 3회 모두 들어오지 않았다(AC-재발견-2). 지금 수집 앱은 `setAppUserModelId`를 호출하지만(`app.ts`), 개발 모드에서 클릭이 되는지는 확인하지 않았다. 리허설에서 클릭이 안 되면 4~5분은 처음부터 트레이 [오늘의 별 보기]로 보여 준다. 알림은 "뜨는 것"까지만 보여 준다.

| 순서 | 할 일 | 왜 |
| --- | --- | --- |
| 1 | 수집 앱을 끈다 (트레이 → 종료) | 앱이 켜져 있으면 서버가 보관함 폴더를 잡고 있어 이름 바꾸기가 실패할 수 있다. 앱이 `settings.json`을 다시 써서 4번에서 고친 값이 덮어써질 수 있다 |
| 2 | 앱이 쓰는 보관함 폴더의 이름을 바꿔 둔다. 폴더 위치는 `settings.json`의 `vaultPath` 값이다. 그 값이 없으면 기본값 `문서/SpaceLog`다(윈도우 '문서'가 OneDrive로 옮겨져 있으면 그쪽) | 시드 스크립트는 별이 이미 있는 보관함을 거부한다. 리허설 기록도 섞이지 않는다 |
| 3 | 저장소 루트에서 `npm install`(처음 한 번), 그다음 `node apps/server/vault/seed.ts "<2번의 vaultPath>"`. 출력이 **"별 23개를 넣었어요. 7일 전(2026-11-05) 3개 · 오늘 6개"** 인지 본다 | 재발견 후보가 들어갔는지 확인한다. 폴더는 스크립트가 만든다 |
| 4 | `settings.json`의 `lastNotifiedLocalDate`가 `"2026-11-12"`이면 `null`로 바꾼다 (기본값이 `null`이다) | 아침 리허설에서 알림이 이미 떴으면 발표 때 다시 뜨지 않는다 |
| 5 | 알림 시각을 정해 앱을 켠다. PowerShell 기준: `$env:SPACELOG_NOTIFY_AT="HH:MM"; npm start` (`apps/collector`에서 실행). `HH:MM`은 **발표 시작 시각 + 4분**(벽시계 기준)으로 잡는다 | 알림은 1분 단위로 확인하므로 최대 1분 늦게 뜬다. 발표가 밀려 알림이 1~3분 장면에 먼저 뜨거나 뜨지 않으면, 4~5분은 트레이 [오늘의 별 보기] 또는 재발견 카드로 보여 준다(1장 4~5분 대안) |

- **확인한 것 (PO, 2026-11-11)**
  - main 코드로 시드를 11/12 08:00 · 09:00 · 10:30(KST)에 넣는 경우를 돌렸다. 세 경우 모두 별 23개, 이번 주 20개, 오늘 6개, 미래 시각 0개, 재발견 7일 전 후보가 있었다. 11/11 17:00에 넣고 11/12 09:30에 조회하면 후보가 없었다.
  - 3번 명령을 윈도우 · Node 24.21에서 빈 폴더에 실행했다. 출력은 "별 23개를 넣었어요. 7일 전(2026-11-04) 3개 · 오늘 6개"였고(11/11 실행이라 11-04), 같은 폴더에 다시 실행하면 "이미 별이 있는 보관함이에요"로 거부됐다.
  - 1·4·5번의 근거는 코드를 읽어 확인했다. 실행해 보지는 않았다.
- **확인하지 않은 것**
  - 1~5번을 데모 PC에서 이어서 해 보지 않았다.
  - `settings.json` 위치는 Electron 기본 규칙상 윈도우 `%APPDATA%\SpaceLog\`, 맥 `~/Library/Application Support/SpaceLog/`로 **추정**한다. 맥 절차는 확인하지 않았다.
  - 개발 B가 리허설 전에 한 번 해 보고, 실제 경로를 여기에 적는다.
- 아침 리허설에서 알림을 본 뒤 발표에서 다시 보려면 **1~4번을 다시 하고 5번으로 켠다.**

### 축소했을 때의 데모

PRD 3장의 축소 순서(MCP 리소스 형식 → 착륙 연출 → 행성 합치기)를 적용해도 위 8분은 그대로 간다. MCP 리소스 라디오가 없고, 바로 가기가 연출 없이 이동하고, 합치기 메뉴가 없을 뿐이다. **모으기와 재발견(1~5분)은 줄이지 않는다.**

**썸네일도 이번 범위에서 뺐다 (2026-11-11 PO, PRD 3장).** 별 목록·별 상세·재발견 카드의 썸네일 자리에 **종류 아이콘**(이미지·파일·링크·텍스트)이 보이고, 링크는 제목 대신 도메인이 보인다. 화면이 비지는 않는다 (SPEC 1-5, P 2-7의 대체 규칙). 데모에서 이 장면이 나오면 **"썸네일과 링크 제목은 다음 단계입니다"** 라고 말한다. 보여 주는 화면과 다른 말을 하지 않기 위해서다.

- [ ] **발표 당일 아침에** 새 보관함에 시드 데이터 들어감 (7일 전 별 3개 이상 확인, 1장 "발표 당일 아침 순서")
