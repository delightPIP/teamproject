# 📄 PRD: 우주 아카이브 (가칭)

> **상태**: 1차 초안 (검토 중) · 2026-11-11
> **공유 문서**: [Claude Docs 버전](https://claude.ai/artifact/E64bsV5PcgEMGBeKRAVk5o) (코멘트·공동 편집용)
> **근거 문서**: [docs/RESEARCH.md](RESEARCH.md)

맥·윈도우의 아주 가벼운 수집 앱으로 드래그앤드롭 한 번에 기록을 모으고, 웹사이트에서 카테고리별 우주로 한눈에 보며, 고른 묶음을 Claude로 보낸다. **앱은 모으기만, 보기·정리·보내기는 웹이 맡는다.**

## 1. 배경 및 문제 정의 (Why & Who)
- **타깃 사용자**: PC(맥·윈도우)로 일하거나 공부하며 하루에도 캡처, 문서, 링크, 메모를 많이 접하는 사람. 20~30대를 1차 타깃으로 가정한다.
  - ⚠️ 연령은 아직 근거가 없는 가정이다. 인터뷰로 확인한다.
- **해결할 핵심 문제**: 다운로드 폴더, 캡처, 카톡 나와의 채팅, 메모앱에 흩어 저장하기만 하고, 모은 것을 한눈에 정리하지 못하며, AI에 쓰려면 다시 찾아 하나씩 옮겨야 한다.
  - [근거] 사용자는 저장한 콘텐츠를 거의 다시 보지 않는다 (Schneegass 2021).
  - [근거] 찍은 사진의 70%는 다시 보지 않는다 (Popsa 2026).
  - [근거] 지식노동자는 하루 수천 번 앱을 전환한다 (Vaid & Whillans 2026).
- **제공할 가치**:
  1. **모으기가 쉽다**: 늘 떠 있는 창에 끌어다 놓기만 하면 된다.
  2. **쌓인 게 보인다**: 웹사이트에서 모은 것이 카테고리별 우주로 자라 한눈에 보인다.
  3. **다시 만난다**: 지난 자료가 별로 다시 떠올라 재발견하게 된다. [근거] 사람들은 평범한 과거 기록을 다시 보는 즐거움을 과소평가한다 (Zhang 2014).
  4. **AI로 바로 넘긴다**: 고른 묶음을 정리된 형태로 Claude 등에 보낸다.

## 2. 목표 및 핵심 성공 기준
- 사용자가 자료 하나를 **드래그 한 번, 3초 안에** 수집 앱에 넣을 수 있어야 한다.
- 수집 앱은 **가볍다**: 바로 뜨고, 넣고 나면 곧바로 하던 일로 돌아갈 수 있으며, 다른 작업을 방해하지 않는다. 구체 수치(실행 시간, 메모리)는 Q3에서 정한다.
- 사용자가 웹사이트에서 **오늘 모은 것을 카테고리별로 한눈에** 확인할 수 있어야 한다.
- 사용자가 탐사를 마치고 **1분 안에** 고른 묶음을 Claude로 보낼 수 있어야 한다.
- (MVP 이후 지표 후보) 7일 재방문율, 주당 탐사선 발사 횟수, 재발견된 별을 열어본 비율.

## 3. 기능 범위 (Scope)

MVP는 가벼운 수집 앱 1개와 웹사이트의 기능 3개로 구성하며, 가장 중요한 것은 수집 앱이다. 앱에는 모으기 외의 기능을 넣지 않는다.

### ✅ 필수 구현 기능 (In-Scope MVP)
1. **수집 앱 (맥·윈도우) — 제품의 핵심**
   - 메뉴바·트레이에 조용히 상주하는 작은 드롭존.
   - 이미지, 파일, 텍스트, 링크를 드래그앤드롭, 붙여넣기, 단축키로 넣으면 기록 1개(별 1개)가 저장된다.
   - 원하면 한 줄 메모나 카테고리를 붙일 수 있다. 건너뛰어도 된다.
   - "우주 보기" 버튼으로 웹사이트를 연다.
   - 보기, 정리, 보내기 화면은 앱에 두지 않는다. 바로 뜨고 바로 사라지는 가벼움이 우선이다.
2. **우주 웹 (한눈에 보기)**
   - 기간(오늘 / 이번 주 / 직접 지정)을 고르면 그 기간의 기록이 우주로 그려진다.
   - 카테고리 = 행성, 기록 = 행성 주변의 별. 기록이 많은 행성일수록 크게 보인다.
   - 별을 누르면 원본(이미지 미리보기, 파일, 링크)을 본다. 카테고리를 바꾸는 정리도 여기서 한다.
3. **탐사선 (웹에서 AI로 보내기)**
   - 기간이나 카테고리 단위로 기록을 골라 묶는다.
   - 보내기 전에 무엇이 나가는지 **미리보기**로 확인한다. 사용자가 고른 것만 나간다.
   - 묶음을 Claude가 읽기 좋은 형태(정리된 텍스트 + 첨부)로 만들어 보낸다.
   - [근거] 국내 20~60대의 88.7%가 AI의 본인 개인정보 침해를 우려한다 (한국언론진흥재단 2025). 그래서 자동 전송은 하지 않는다.
4. **재발견 (웹 첫 화면의 다시 떠오르는 별)**
   - 웹사이트를 열면 "N일 전 오늘 모은 별"을 하나 띄워 보여준다.
   - [근거] 주기적 알림이 있으면 저장한 콘텐츠를 다시 본다 (Sigethy 2025).

### 🚫 이번에 제외할 기능 (Out-of-Scope)
- [ ] 수집 앱 안에서 우주 보기, 정리, 보내기 (모두 웹에서)
- [ ] 모바일 앱
- [ ] 다른 사람과 우주 공유, 협업
- [ ] MCP 서버로 AI가 내 우주를 직접 조회하는 기능 (다음 단계)
- [ ] 3D 그래픽, 화려한 우주 애니메이션 (2D로 시작)
- [ ] 기록 내용을 편집하는 기능
- [ ] 자동 백그라운드 수집 (다운로드 폴더 감시, 클립보드 자동 저장 등)
- [ ] 로그인과 클라우드 동기화는 Q6 결정에 따른다. 로컬 웹으로 가면 MVP에서 제외한다.

## 4. 유저 저니 (핵심 흐름)
낮에는 앱에 모으고, 하루의 끝에 웹에서 둘러보고 보낸다.

1. PC를 켜면 수집 앱이 메뉴바·트레이에 조용히 떠 있다.
2. 일하다가 마음에 드는 캡처, 문서, 링크를 드롭존에 끌어다 놓는다. 원하면 한 줄 메모를 붙이고, 곧바로 하던 일로 돌아간다.
3. 하루를 마치며 앱의 "우주 보기"를 눌러 웹사이트를 연다.
4. 웹 첫 화면에 "7일 전 오늘의 별"이 하나 떠오른다. 눌러서 그때 모은 기록을 다시 본다.
5. 오늘 모은 기록이 카테고리별 행성으로 보인다. 필요하면 카테고리를 고친다.
6. 보내고 싶은 행성이나 별을 골라 탐사선 미리보기로 확인하고 Claude로 보낸다.
7. Claude에서 정리된 묶음을 바탕으로 요약하거나, 기록하거나, 다음 작업을 이어간다.

## 5. 피처 오너십 (1차안)

팀 6명(개발 4, 디자이너 1, PO 1)이 한 사람당 빅 피처 하나를 처음부터 끝까지 맡는다. 개발 4명은 서로 다른 영역을 맡아 병렬로 작업하고, 디자이너와 PO는 작은 범위의 피처를 맡는다.

| 오너 | 빅 피처 | 맡는 범위 | 크기 | 먼저 필요한 것 |
| --- | --- | --- | --- | --- |
| 개발 A | **수집 앱** | 가벼운 데스크톱 앱 뼈대, 메뉴바·트레이 드롭존, 드래그앤드롭·붙여넣기·단축키 입력, 한 줄 메모, 웹 열기, 가벼움 목표(실행 속도·메모리) 달성 | 대 | Q3 기술 스택 |
| 개발 B | **별 저장소 + 연결 API + 행성 엔진** | 기록·원본 파일 저장, 썸네일·메타데이터, 앱이 넣고 웹이 읽는 API, 기간별 조회, 카테고리 제안·수정 | 대 | 데이터 모델 합의(1일 차), Q1, Q6 |
| 개발 C | **우주 웹 + 재발견** | 웹 앱 뼈대, 2D 우주 렌더링, 행성 크기·배치, 확대·이동, 기간 선택, 별 상세 미리보기, 카테고리 수정 화면, "N일 전 오늘의 별" | 대 | 연결 API 인터페이스, 디자이너 비주얼 가이드 |
| 개발 D | **탐사선 (웹)** | 기록 선택, 보내기 전 미리보기, 묶음 생성(텍스트 + 첨부), Claude 전송, 개인정보 가드 | 대 | Q2 전송 방식, PO 탐사 일지 템플릿 |
| 디자이너 | **우주 비주얼 가이드** | 별·행성 표현 규칙(크기, 색, 밝기의 의미), 컬러 토큰, 수집 앱 드롭존과 탐사선 미리보기 화면 디자인 | 소 | 없음 |
| PO | **탐사 일지 템플릿 + 검증** | Claude에 보낼 묶음의 구조와 안내 문구 설계, 사용자 인터뷰 5~8명, 데모 시나리오와 인수 기준 | 소 | 없음 |

**공통 약속**
- **1일 차에 데이터 모델을 먼저 합의한다.** 별(기록)과 행성(카테고리)의 필드는 개발 B가 초안을 내고 개발 4명이 함께 확정한다. 확정 전에는 가짜 데이터로 작업한다.
- **기술 스택(Q3)은 개발 A가 `/adr`로 비교해 1일 차에 정한다.**
- 디자이너 결과물은 개발 C(우주 웹)와 개발 A·D(드롭존, 탐사선 화면)가 받아 쓴다.
- PO의 탐사 일지 템플릿은 개발 D(탐사선)가 받아 쓴다.
