# 📄 PRD: SpaceLog

> **상태**: 1차 초안 (검토 중) · 2026-11-11 · 사용자 인터뷰 후 2차 개정 예정
> **공유 문서**: [Claude Docs 버전](https://claude.ai/artifact/E64bsV5PcgEMGBeKRAVk5o) (코멘트·공동 편집용)
> **근거 문서**: [docs/RESEARCH.md](RESEARCH.md) — 본문의 `C-xx`는 이 문서의 주장 ID다. `팀 결정`은 근거가 아니라 팀이 정한 것이다.

맥·윈도우의 아주 가벼운 수집 앱으로 드래그앤드롭 한 번에 기록을 모으고, 로컬 웹의 3D 우주에서 한눈에 보고 날아다니며 다시 만나고, 고른 묶음을 Claude용으로 내보낸다. **수집 앱은 모으기만, 보기·정리·내보내기는 앱이 내 PC에 띄우는 로컬 웹이 맡는다. 기록은 내 PC에만 저장된다.**

## 1. 배경 및 문제 정의 (Why & Who)
- **타깃 사용자**: PC(맥·윈도우)로 일하거나 공부하며 하루에도 캡처, 문서, 링크, 메모를 많이 접하는 사람. 20~30대를 1차 타깃으로 가정한다.
  - ⚠️ 연령은 근거가 없는 가정이다 (C-01·C-02 공백). 인터뷰로 확인한다 (Q4).
- **해결할 핵심 문제**: 다운로드 폴더, 캡처, 카톡 나와의 채팅, 메모앱에 흩어 저장하기만 하고 **다시 보게 하는 장치가 없다**. 그래서 모은 것을 한눈에 정리하지 못하고, 모아둔 자료와 생각이 묻히고 잊힌다.
  - 저장한 콘텐츠를 거의 다시 보지 않는다 — C-03, Schneegass 2021 (해외, 설문 N=58, 연령 정보 없음).
  - 찍은 사진의 70%는 다시 보지 않는다 — C-12, Popsa 2026 (미·영·프·독 기업 조사, 측정 방법 미공개).
  - 메신저 나와의 채팅을 기록용으로 쓴다 — C-04, 카카오 2019 (국내, 수치 없음).
  - 기록해도 세부 사항은 빨리 잊히며, 되짚으면 회상에 도움이 된다 — C-05, Kristo 2009. 단 의미 있는 기억은 꼭 잊히지 않으므로(Radvansky 2024) 손해를 과장하지 않는다.
  - (간접) 지식노동자는 하루 수천 번 앱을 전환한다 — C-10, Vaid & Whillans 2026 (기업 대상, 동료심사 전). 흩어짐의 간접 신호로만 쓴다.
- **부가 문제 (근거 공백)**: AI에 쓰려면 자료를 다시 찾아 하나씩 옮겨야 한다. 근거는 기업 대상 조사뿐이고(C-13), 개인 사용자 근거는 공백이다. 인터뷰로 확인한다.
- **제공할 가치**:
  1. **모으기가 쉽다**: 화면에 떠 있는 작은 드롭존에 끌어다 놓기만 하면 된다.
  2. **다시 만난다**: 지난 기록이 알림과 첫 화면 카드로 다시 떠오른다. 사람들은 평범한 과거 기록을 다시 보는 즐거움을 과소평가한다 — C-08, Zhang 2014 (공저자 Gino 논란으로 인용 주의).
  3. **쌓인 게 보인다**: 모은 기록이 행성으로 자라 우주 전체가 한눈에 보인다 (진척이 보이면 지속 동기가 오른다 — C-07, Harkin 2016, 간접).
  4. **둘러보는 재미가 있다**: 우주를 날아다니며 행성에 착륙해 기록을 살펴본다 (팀 결정, 근거 없음).
  5. **AI용으로 바로 내보낸다**: 고른 묶음을 Claude가 읽기 좋은 형식으로 만든다 (보조 가치, 수요 검증 대상).

## 2. 목표 및 핵심 성공 기준

측정 방법과 최종 수치는 PO가 확정한다. 사용 기록은 서버로 보내지 않고 내 PC에만 남기며, 인터뷰·데모 때 사용자 동의를 받아 함께 확인한다.

| 기준 | 측정 시작 → 끝 | 목표 | 수치 확정 |
| --- | --- | --- | --- |
| 모으기가 빠르다 | 파일을 드롭존에 놓은 순간 → 저장 완료 표시 | 3초 이내 | 확정 |
| 수집 앱이 가볍다 | 앱 + 로컬 서버의 실행 시간, 대기 중 메모리 | PO·개발 B가 Q3에서 제안 | PO, 1주 차 |
| 한눈에 보인다 | 웹 첫 화면 진입 → 조작 없이 기본 기간의 행성 전체가 보임 | 조작 0회 | 확정 |
| 비행 없이도 찾는다 | 우주 홈 → 클릭만으로 원하는 행성 패널 열림 | 클릭 2회 이내 | 확정 |
| 3D가 부드럽다 | 기준 별 개수에서 일반 노트북의 프레임 수 | 개발 C가 1주 차에 측정해 제안 | PO, 1주 차 |
| 다시 만난다 (핵심) | 재발견 알림·카드가 뜬 횟수 → 사용자가 열어본 횟수 | 데모·인터뷰 기간에 측정 | PO, 인터뷰 후 |
| 내보내기가 빠르다 | 탐사선 열기 → 복사 완료 | 1분 이내 | 확정 |

(MVP 이후 지표 후보) 7일 재방문율, 주당 내보내기 횟수.

## 3. 기능 범위 (Scope)

가장 중요한 두 축은 **모으기(수집 앱)**와 **다시 만나기(재발견)**다. 모으기는 입구이고, 재발견은 문제정의의 핵심을 직접 해결한다. 마감이 짧으면 **탐사선의 MCP 리소스 형식 → 비행 탐색의 착륙 연출 → 행성 합치기** 순서로 줄이고, 재발견과 수집 앱은 줄이지 않는다.

### ✅ 필수 구현 기능 (In-Scope MVP)
1. **수집 앱 (맥·윈도우)**
   - **형태**: 화면 가장자리에 작게 접혀 떠 있는 드롭존 창 + 메뉴바·트레이 아이콘. 윈도우 트레이 아이콘은 파일 드롭을 받지 못하므로 드롭은 떠 있는 창이 받는다.
   - **넣기**: 이미지, 파일, 텍스트, 링크를 드래그앤드롭하거나 붙여넣으면 기록 1개가 저장된다. 전역 단축키를 누르면 지금 클립보드에 있는 내용이 바로 기록된다.
   - **넣은 직후 확인**: 자동 배정된 행성을 보여주고, 그 자리에서 한 번만 한 줄 메모를 붙이거나 행성을 바꿀 수 있다. 건너뛰어도 된다. 이후의 정리는 모두 웹에서 한다.
   - **재발견 알림**: 하루 한 번 운영체제 알림으로 "7일 전 오늘의 별"을 알려준다. 누르면 웹이 그 별로 열린다. 알림은 끌 수 있다.
   - **기타**: "우주 보기" 버튼으로 로컬 웹 열기, 로그인 시 자동 실행, 설정(단축키, 알림 켜기·끄기, 보관함 위치).
   - 보기, 정리, 내보내기 화면은 앱에 두지 않는다.
2. **3D 우주 (로컬 웹)**
   - **조망 시점**: 웹을 열면 기본 기간 **오늘**의 우주 전체가 한 화면에 보인다. 기간(오늘 / 이번 주 / 직접 지정)을 바꿀 수 있다. 오늘 기록이 0개면 이번 주로 넓혀 보여주고 그렇게 했다고 알려준다.
   - **행성과 별**: 기록이 많은 행성일수록 크다. 별은 행성 주변을 돈다.
   - **비행 탐색** (팀 결정): 키보드(WASD 이동, Space·Shift 상승·하강)와 마우스 드래그(시점)로 날아다닌다.
   - **착륙**: 행성 가까이에서 E 키 또는 클릭으로 착륙하면 행성 패널이 열린다.
   - **바로 날아가기**: 행성 목록에서 하나를 누르면 그 행성까지 자동으로 날아가 패널을 연다. 비행 조작을 모르는 사용자의 기본 경로다.
   - **재발견 카드**: 첫 화면에 "7일 전 오늘의 별" 카드를 띄운다. 누르면 그 별이 있는 행성으로 날아간다.
3. **행성 패널과 별 상세 (로컬 웹)**
   - **행성 패널**: 이 행성의 별 목록, 행성 이름 바꾸기, 새 행성 만들기, 빈 행성 삭제, 다른 행성과 합치기, 탐사선에 싣기.
   - **별 상세**: 원본 미리보기(이미지, 파일 이름, 링크 제목, 텍스트), 원본 열기(운영체제 기본 앱) / 폴더에서 보기, 메모 수정, 다른 행성으로 옮기기, 기록 삭제.
   - 원본 파일 자체는 편집하지 않는다. 메모와 행성만 바꿀 수 있다.
4. **탐사선 (로컬 웹) — 보조 기능, 수요 검증 대상**
   - **싣기**: 별 몇 개, 행성 하나, 또는 기간 안의 우주 전체를 고른다.
   - **형식**: Claude 프롬프트 형식(정리된 텍스트) 또는 MCP 리소스 형식(나중에 MCP 서버가 그대로 내어줄 JSON).
   - **미리보기 후 복사**: 무엇이 나가는지 미리보기로 확인하고 복사한다. 사용자가 고른 것만 나간다. 자동 전송은 하지 않는다 (Q2 잠정).
   - [리스크 근거] 국내 20~60대의 88.7%가 "개인정보에 관한 내 권리"를 AI가 침해할까 걱정한다 — C-09, 한국언론진흥재단 2025 (기사로 확인).
   - **축소 조건**: 인터뷰에서 대부분이 AI에 자료를 넣어본 경험이 없으면, 탐사선은 Claude 프롬프트 형식 복사만 남기고 줄인다.

### 🚫 이번에 제외할 기능 (Out-of-Scope)
- [ ] 수집 앱 안에서 우주 보기, 정리, 내보내기 (넣은 직후 1회 확인만 허용)
- [ ] 웹에서 새 기록 만들기 (모으기는 수집 앱이 전담)
- [ ] 외부 AI로 행성 자동 분류 (기록이 PC 밖으로 나가므로)
- [ ] 검색, 태그 (MVP는 기간 선택과 행성 목록으로 찾는다)
- [ ] 원본 파일 편집
- [ ] 로그인, 회원가입, 클라우드 동기화, 백업, 다른 기기에서 보기 (로컬 웹으로 결정)
- [ ] 모바일 앱, 터치 조작
- [ ] 다른 사람과 우주 공유, 협업
- [ ] MCP 서버로 AI가 내 우주를 직접 조회하는 기능 (다음 단계. MVP는 MCP 리소스 형식의 복사까지)
- [ ] Claude로 자동 전송, Claude 앱 연동
- [ ] 자동 백그라운드 수집 (다운로드 폴더 감시, 클립보드 자동 저장 등)

## 4. 유저 저니 (핵심 흐름)
낮에는 수집 앱에 모으고, 알림이나 하루의 끝에 우주에서 다시 만나고 둘러본 뒤, 필요하면 내보낸다.

1. PC를 켜면 수집 앱이 자동 실행되어 드롭존이 화면 가장자리에 작게 떠 있다.
2. 일하다가 마음에 드는 캡처, 문서, 링크를 드롭존에 끌어다 놓는다. 배정된 행성을 확인하고, 원하면 한 줄 메모를 붙이고, 곧바로 하던 일로 돌아간다.
3. 오후에 "7일 전 오늘의 별" 알림이 뜬다. 누르면 우주가 열리고 그 별이 있는 행성으로 날아간다.
4. 하루를 마치며 수집 앱의 "우주 보기"로 웹을 연다. 조망 시점에서 오늘 모은 행성 전체가 보인다.
5. 날아다니거나 행성 목록에서 바로 날아가 행성에 착륙한다. 행성 패널에서 별을 열어보고, 필요하면 행성을 옮기거나 합친다.
6. 필요한 별이나 행성을 탐사선에 싣고, 형식을 골라 미리보기로 확인한 뒤 복사한다.
7. Claude에 붙여넣어 요약하거나 다음 작업을 이어간다.

## 5. 화면 구조 (뼈대)

## 6. 피처 오너십

팀 6명(PO 1, 디자이너 2, 개발 3)이 한 사람당 빅 피처 하나를 처음부터 끝까지 맡는다. 수집 앱은 PO가 직접 만들고, 개발자 3명은 웹과 데이터에 집중한다. 3D와 우주 홈은 개발 C, 정리 화면(행성 패널, 별 상세)은 데이터를 다루는 개발 B, 재발견과 탐사선은 개발 A가 맡는다.

| 오너 | 빅 피처 | 맡는 범위 | 크기 | 먼저 필요한 것 |
| --- | --- | --- | --- | --- |
| PO | **수집 앱 + 검증** | 데스크톱 앱 뼈대, 드롭존 창, 드래그앤드롭·붙여넣기·전역 단축키, 넣은 직후 확인, 로컬 서버 실행·종료 연결, 자동 실행, 설정, 재발견 알림 표시, 앱+서버 가벼움 목표 달성(B와 공동), 사용자 인터뷰 5~8명, 성공 기준 수치 확정, 데모 시나리오와 인수 기준 | 대 | Q3 기술 스택 |

**공통 약속**
- **1일 차에 데이터 모델과 API 목업을 먼저 합의한다.** 개발 B가 초안을 내고 개발 3명과 PO가 확정한다. 확정 전에는 목업으로 작업한다. 기록에는 최소한 종류(이미지·파일·링크·텍스트), 보관함 안의 원본 위치, 원래 파일 이름, 썸네일, 메모, 행성, 넣은 시각이 필요하다. 재발견의 "7일 전"은 넣은 시각을 기준으로 한다.
- **원본은 보관함에 복사해 저장한다.** 사용자가 다운로드 폴더를 정리해도 기록이 깨지지 않게 하기 위해서다. 디스크 사용량은 설정에서 보이게 한다.
- **로컬 서버는 개발 B가 만들고, PO가 수집 앱과 함께 켜고 끈다.** 서버는 이 PC 안에서만 접속되게 하고, 다른 웹페이지가 호출하지 못하게 막는다.
- **기술 스택(Q3)은 PO와 개발 B가 함께 `/adr`로 비교해 1일 차에 정한다.** 웹 스택(Q9)은 개발 B·C가 함께 정한다.
- **웹 화면 계약을 1주 차 초에 개발 A·B·C가 합의한다**: 선택된 기간, 선택된 행성, 탐사선에 실은 목록, "이 행성으로 날아가기"와 "패널 열기" 호출을 어떻게 주고받는지.
- **디자이너 2명은 1주 차 초에 컬러 토큰과 공통 요소(버튼, 패널 틀)를 먼저 맞춘다.** 디자이너 1이 컬러 토큰을 내고 디자이너 2가 받아 쓴다.
- 3D 장면의 행성·별은 개발 C가 단순한 도형으로 만들고, 디자이너 1은 색과 테마 규칙만 준다. 3D 모델링은 하지 않는다.
- 링크 기록은 링크 제목·썸네일을 가져오려고 해당 사이트에 접속한다. 이때 기록 내용은 보내지 않는다.
- **재발견 알림은 개발 A가 고른 별을 PO의 수집 앱이 띄운다.** 연결 방식은 1주 차 초에 PO와 개발 A가 맞춘다.
- 개발이 3명이라 일정이 빠듯하다. 1주 차 끝에 진척을 보고 필요하면 3장의 축소 순서를 적용한다. 개발 B의 범위가 가장 넓으므로, 그때 행성 패널을 개발 A로 옮길 수 있다.

## 8. 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 3D 비행이 "한눈에 보기"를 방해한다 | 기록을 찾기 어려워진다 | 기본 화면은 조망 시점, 바로 날아가기를 기본 경로로 둔다 |
| 비행 조작이 익숙하지 않은 사용자 | 처음 쓰는 사람이 이탈한다 | 클릭만으로 행성 도착·착륙이 되게 하고, 조작 안내를 화면에 둔다 |
| 별이 많아지면 3D가 느려진다 | 우주가 끊기고 PC가 무거워진다 | 1주 차에 성능 기준을 정하고, 기간 선택으로 그리는 별 수를 줄인다 |
| 3D 작업량이 커서 개발 C 일정이 밀린다 | 웹 전체가 늦어진다 | 정리 화면은 개발 B, 탐사선은 개발 A로 나눴다. 3장의 축소 순서를 따른다 |
| 자동 배정된 행성이 자주 틀린다 | 행성이 엉뚱하게 묶인다 | 넣은 직후 배정된 행성을 보여주고 바로 바꿀 수 있게 한다 |
| 윈도우 트레이 아이콘은 파일 드롭을 받지 못한다 | 윈도우에서 모으기가 막힌다 | 드롭은 떠 있는 드롭존 창이 받는다. Q3 비교 항목에 넣는다 |
| 로컬 서버를 다른 웹페이지가 호출한다 | 내 기록이 새어 나간다 | 이 PC 안에서만 접속, 다른 출처의 요청 차단 (개발 B) |
| 로컬 전용이라 백업이 없다 | PC 고장 시 기록을 잃는다 | 보관함 위치를 설정에서 보여주고 직접 백업할 수 있게 한다. 자동 백업은 다음 단계 |
| 탐사선 수요가 없다 | 개발 A의 작업이 쓰이지 않는다 | 3장 4번의 축소 조건을 따른다 |
| 개발자가 3명이다 | 필수 기능을 다 만들지 못한다. 특히 개발 B의 범위가 넓다 | 1주 차 끝에 진척을 보고 3장의 축소 순서를 적용한다. 개발 B는 API 목업을 1일 차에 내서 다른 사람을 막지 않는다 |
| PO가 수집 앱 개발과 PO 업무를 함께 맡는다 | 결정·인터뷰가 늦어지거나 수집 앱이 늦어진다 | 수집 앱은 3장의 범위를 넘기지 않는다. 결정이 필요한 질문은 담당 개발자가 먼저 안을 내고 PO는 고르기만 한다 |
