# 🎤 리허설 진행표 (REHEARSAL)

> **상태**: 2026-11-11 작성 · **발표 2026-11-12 오전** · 담당 PO · [DEMO.md](DEMO.md) 1장을 발표자가 보면서 읽을 수 있게 옮긴 것
> 이 문서는 **무대에서 손에 들고 보는 종이**다. 기준과 근거는 DEMO.md에 있고, 여기에는 **할 것과 할 말, 막혔을 때의 대안**만 둔다.
> 데모 PC는 윈도우라서 명령은 **PowerShell 기준**이다.

## 0. 시작 전 (5분)

DEMO 1장 "발표 당일 아침 순서" 2~4번(보관함 비우기·시드·알림 기록 지우기)을 스크립트 한 번으로 한다.

> **실서버일 때만 이 순서를 쓴다.** 가짜 서버(`SPACELOG_SERVER_ENTRY=dev/mockServer.mjs`)는 보관함을 쓰지 않아 재발견 후보가 없다. 그때는 4~5분을 생략하고 "재발견은 실서버에서 동작합니다"라고 말한다 (DEMO 1장 전제).

PowerShell 창을 **두 개** 쓴다. ① 저장소 루트 창(스크립트·빌드), ② 수집 앱 창(`apps/collector`). ①에서 `cd`하지 않아야 다시 돌리기·`--restore`가 경로를 찾는다.

1. **수집 앱을 끈다** (트레이 → 종료). 켜져 있으면 앱이 `settings.json`을 다시 써서 바꾼 값이 덮어써지고, 서버가 보관함 폴더를 잡고 있어 지우기가 실패할 수 있다.
2. ① 창(저장소 루트)에서 준비한다. Node 24가 필요하다(시드 스크립트 `.ts`를 node로 바로 실행, 확인한 환경 Node 24.21).

   ```powershell
   npm install                          # 처음 한 번
   npm run build -w @spacelog/web       # web/dist가 없을 때. 없으면 "우주 보기"가 빈 화면
   node scripts/demo-reset.mjs --at HH:MM
   ```

   - `HH:MM`은 **발표 시작 시각 + 4분**(벽시계 기준, DEMO 1장 5번). 리허설에서는 `--at`을 빼면 지금부터 4~5분 뒤(분 단위 올림)로 잡힌다.
   - 하는 일: 데모 보관함(`%USERPROFILE%\Documents\SpaceLog-demo`, 실제 경로는 스크립트가 출력)을 비우고 **실행 시각 기준으로** 다시 시드한다(7일 전 별 3개 + 이번 주 20개, 행성 4곳). 수집 앱 설정(`settings.json`)을 이렇게 바꾼다: 보관함 위치 → 데모 보관함, `lastNotifiedLocalDate` → 비움(오늘 알림을 다시 받음), `launchAtLogin` → 끔(리허설 중 로그인 자동 실행 등록 안 함), `onboardingDone` → 켬(첫 실행 안내 건너뜀). 처음 바꿀 때 원래 설정을 `settings.before-demo.json`에 남긴다.
   - 출력에 **"별 23개를 넣었어요. 7일 전(2026-11-05) 3개 · 오늘 6개"**(11/12 실행 기준)가 있는지 본다.
   - 폴더 이름에 `demo`가 없으면 지우지 않고 멈춘다. 평소 보관함(`문서/SpaceLog`)은 건드리지 않는다.
3. ② 창에서, 스크립트가 마지막에 출력한 명령으로 앱을 띄운다:

   ```powershell
   cd apps/collector; $env:SPACELOG_NOTIFY_AT="HH:MM"; npm start
   ```

> **시드는 발표 당일 아침에 넣는다.** 시드는 실행한 날 기준으로 7일 전 별을 만들어서, 11/11에 넣으면 11/12에는 8일 전이 되어 재발견이 뜨지 않는다 (DEMO 1장).

**확인하지 않은 것 (2026-11-11 PO).** 스크립트는 임시 폴더(`APPDATA`와 보관함을 임시 경로로 지정)에서 시드·설정 변경·재실행·`--restore`·안전장치를 돌려 확인했다. **데모 PC에서 0장 전체를 이어서 해 본 적은 없다.** 앱이 켜진 채 실행했을 때 지우기 실패 메시지가 나오는지도 확인하지 않았다. 아침 리허설에서 처음 확인한다.

| 확인 | 왜 |
| --- | --- |
| [ ] 설정 창에 "개발용 SPACELOG_NOTIFY_AT로 알림 시각이 …로 바뀌어 있어요"가 보인다 | 알림 시각이 들어갔는지 (DEMO 4장) |
| [ ] 드롭할 자료 4개를 바탕화면에 모아 둔다: 캡처 이미지 · PDF · 링크(브라우저 탭) · 텍스트 한 줄 | 무대에서 파일 찾지 않기 |
| [ ] 브라우저에 다른 탭 없이, 한 번 열어 WebGL이 되는지 본다 | AC-우주-7 |
| [ ] 트레이 아이콘이 보이고 드롭존이 가장자리에 접혀 있다 | 0~1분 장면 |
| [ ] **알림이 실제로 뜨는지** 리허설에서 한 번 본다 | 가장 많이 깨지는 곳 |
| [ ] **알림을 클릭하면 브라우저가 그 별 상세로 열리는지** 본다. 안 되면 발표 4~5분은 처음부터 트레이 [오늘의 별 보기]로 하고, 알림은 "뜨는 것"까지만 보여 준다 | 개발 모드 알림 클릭은 확인하지 않았다 (DEMO 1장 ⚠, AC-재발견-2) |

> **리허설을 두 번 하려면, 그리고 아침 리허설 뒤 발표 직전에도 매번 앱을 끄고 `demo-reset.mjs`를 다시 돌린다.** 시드는 별이 있는 보관함에 넣지 않고, 재발견 알림은 하루 1번이라 그대로 두면 두 번째에는 안 뜬다.

## 1. 8분 진행표

| 분 | 할 것 | 할 말 | 막히면 |
| --- | --- | --- | --- |
| **0~1** | 접힌 드롭존과 트레이 아이콘을 보여 준다 | "PC를 켜면 이렇게 떠 있습니다. **이 앱은 모으기만 합니다.**" | — |
| **1~3** | 캡처 → PDF → 링크 → 텍스트를 하나씩 드롭. 확인 카드에서 행성을 하나 바꾸고 메모 한 줄 | "놓은 순간부터 **3초 안에** 저장됩니다. 정리는 여기서 끝, 나머지는 웹에서" | 행성·메모에서 오류가 뜨면 **아무것도 바꾸지 말고 [완료]**. 멘트: "행성은 자동으로 배정됩니다. 정리는 웹에서 합니다" |
| **3~4** | `Ctrl+Shift+Space`로 클립보드 텍스트 넣기 | "복사만 해 두고 단축키 한 번" | 단축키가 안 먹으면 트레이 메뉴의 [클립보드 넣기] |

| **5~6** | ⌂ 조망으로 돌아가 오늘 → 이번 주로 기간 전환 | "조작 없이 오늘 우주 전체가 보입니다" | 끊기면 기간을 **오늘**로 좁힌다 |
| **6~7** | 행성 목록에서 하나 클릭 → 패널에서 별 열기 → 다른 행성으로 옮기기 → 잠깐 비행 | "둘러보기는 재미, 목록은 길. **클릭 2번이면 어디든**" | 비행이 어색하면 목록 클릭만으로 |
| **7~8** | 별 2개와 행성 1개를 탐사선에 싣고 미리보기 → 복사 → Claude에 붙여넣기 | "내가 고른 것만, 미리 보고, 복사" | 복사가 막히면 "선택했어요, Ctrl+C로" 안내대로 |

## 4. 끝난 뒤

- 수집 앱을 끄고 `node scripts/demo-reset.mjs --restore`로 설정을 데모 전으로 되돌린다. `settings.json`의 보관함 위치·로그인 시 자동 실행·알림 기록이 원래 값으로 돌아간다. 윈도우 로그인 항목 등록은 수집 앱이 **다음에 켜질 때** 그 값으로 다시 맞춘다(`app.ts` 시작 시 `applyLoginItem`, 코드로만 확인). 데모 보관함 폴더는 남는다.
- 리허설에서 깨진 것이 있으면 DEMO 2장 인수 기준의 해당 줄에 적는다. **고치지 못한 것은 발표 멘트에서 뺀다.**
