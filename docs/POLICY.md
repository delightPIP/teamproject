# ⚖️ 서비스 및 기술 정책 (POLICY)

> **상태**: 1차 확정 · 2026-11-11 · 기준 문서 [docs/PRD.md](PRD.md)
> **(잠정)** 표시는 PRD의 열린 질문(Q1·Q3·Q9)이나 1주 차 측정 결과에 따라 바뀔 수 있는 값이다. 괄호 안 이름이 담당자다.

## 1. 보안 및 데이터 거버넌스 정책

**1-1. 기록은 PC 밖으로 나가지 않는다**
- 기록 원본, 메모, 행성 정보, 사용 기록은 모두 보관함(로컬)에만 저장한다. 서버로 보내는 분석이나 텔레메트리는 넣지 않는다.
- 밖으로 나가는 요청은 **링크 제목·썸네일 가져오기** 하나뿐이다. 이때는 해당 URL에 GET 요청만 보낸다. 쿠키, 기록 내용, 메모는 보내지 않는다.
- 탐사선은 사용자가 직접 복사할 때만 내용을 내보낸다. 자동 전송은 하지 않는다.

**1-2. 비밀키**
- MVP에서는 외부 API 키가 필요 없게 만든다. 나중에 키가 생기면 `.env`에서만 관리하고, `.env.example`만 커밋한다. `.gitignore`에 `.env*`를 넣는다(`.env.example`은 예외).

**1-3. 로컬 서버 보안 (개발 B)**
- `127.0.0.1`에만 바인딩한다. `0.0.0.0`은 쓰지 않는다.
- 다른 웹페이지가 호출하지 못하게 한다. `Origin`이 로컬 웹 자신이 아니면 거부하고, CORS는 열지 않는다.
- DNS 리바인딩을 막기 위해 `Host` 헤더가 `127.0.0.1:{port}` 또는 `localhost:{port}`가 아니면 거부한다.
- 수집 앱이 서버를 켤 때마다 **세션 토큰**을 새로 만든다. 웹을 열 때 토큰을 넘기고, API는 토큰이 맞을 때만 응답한다.
- 포트는 기본값부터 시도하고, 이미 쓰고 있으면 다음 포트를 쓴다(최대 10번). 정한 포트는 수집 앱이 웹에 알려준다.

**1-4. 보관함 저장 규칙**
- 원본은 보관함에 **복사**해 저장하고, 사용자의 원래 파일은 건드리지 않는다.
- 저장 순서: 원본 복사 → 기록 저장. 중간에 실패하면 복사한 파일을 지워 **반쪽짜리 기록을 남기지 않는다**.
- 넣은 시각은 UTC와 시간대 오프셋을 함께 저장한다. 화면과 재발견 계산은 PC의 현지 시간을 기준으로 한다.
- 썸네일 생성과 링크 제목 가져오기는 저장이 끝난 **뒤에** 비동기로 한다. "3초 안에 저장 완료"를 지키기 위해서다.

**1-5. 요청 및 캐싱**
- 링크 정보는 저장할 때 **1번만** 가져와 기록에 함께 저장하고, 다시 가져오지 않는다. 시간 제한은 5초, 재시도는 1번이다.
- 썸네일은 한 번 만들어 보관함에 캐시하고, 원본이 바뀌지 않으면 다시 만들지 않는다.
- 웹은 기간을 바꿀 때와 창이 다시 포커스를 받을 때 데이터를 새로 받는다. 실시간 동기화는 MVP에서 하지 않는다.

## 2. 비즈니스 규칙 및 계산 공식

**2-1. 기간**
- **오늘**: 현지 시간 00:00부터 지금까지.
- **이번 주**: 이번 주 **월요일** 00:00부터 지금까지.
- **직접 지정**: 시작일과 종료일을 고른다. 최대 1년까지 고를 수 있다 (잠정, 개발 C의 성능 측정 후 조정).

**2-2. 재발견 별 고르기 (개발 A)**
- 기준일은 "오늘 − 7일"이다. 넣은 시각의 현지 날짜가 기준일과 같은 기록이 후보다.
- 후보가 없으면 14일 전, 30일 전 순서로 찾는다. 문구는 "N일 전 오늘의 별"로 바꾼다.
- 후보가 여러 개면 최근 30일 안에 재발견으로 보여준 별을 빼고, **날짜를 시드로 한 랜덤**으로 고른다. 그래야 알림과 웹 카드가 같은 별을 보여준다.
- 7일, 14일, 30일 전 모두 후보가 없으면 그날은 알림을 보내지 않고, 웹 카드도 띄우지 않는다.
- 알림은 하루 1번, **현지 15:00**에 보낸다 (잠정). 그 시각에 PC가 꺼져 있었으면 같은 날 다음 실행 때 1번 보낸다. 지난 날짜의 알림은 몰아서 보내지 않는다.
- 알림이 뜬 횟수와 열어본 횟수를 로컬에 기록한다. 이 값이 성공 기준 "다시 만난다"의 측정값이다.

**2-3. 행성 자동 배정 (개발 B) — Q1 결정: 키워드 규칙 (2026-11-11)**
- 행성은 "파일 종류"가 아니라 **주제**다. 첫 실행 때 기본 행성 7개(주제 6개 + 미분류)를 만들고, 행성마다 키워드를 둔다.
- 모든 계산은 내 PC 안에서 한다. 외부 AI는 쓰지 않는다 (PRD 3장 제외 범위).

- **비교 대상**: 저장하는 순간(3초 목표 안)에 있는 값만 쓴다.
  - 쓴다: 파일 이름(확장자 제외), 확장자, 링크 URL(도메인·경로), 텍스트 본문 앞 2,000자
  - 쓰지 않는다: 링크 제목(저장 뒤에 가져온다, 1-4), 이미지 내용, PDF 등 파일 본문
- **비교 방법**: 대소문자를 구분하지 않는다. 한글 키워드는 부분 일치("회의록2"에 "회의"), 영문 키워드는 **단어 단위** 일치("mail"에서 "ai"를 찾지 않는다). 도메인은 그 도메인이거나 하위 도메인이면 일치한다(`m.youtube.com` → `youtube.com`).
- **고르는 순서**: ① 도메인이 맞는 행성 → ② 확장자가 맞는 행성 → ③ 키워드가 가장 많이 맞은 행성 → 동점이면 행성 목록 순서(만든 순서).
- **행성 이름도 키워드다.** 사용자가 만든 행성(예: "토익")은 이름이 곧 키워드다. 기본 행성은 위 키워드 + 지금 이름이다. 이름을 바꾸면 새 이름으로 맞춘다.
- 어느 행성에도 맞지 않으면 **"미분류"** 에 넣는다. "미분류"는 이름을 바꾸거나 지울 수 없다.
- 넣은 직후 사용자가 행성을 바꾸면 그 선택을 따른다.
- **키워드 편집** (고도화 후보): 사용자가 행성의 키워드를 직접 고치는 기능. MVP 작업 중 시간이 되면 행성 패널(#5)에 넣고, 1주 차 끝 진척으로 못 하면 다음 단계로 넘긴다. 그 전까지 키워드는 위 표와 행성 이름으로 고정이다.

**2-4. 행성 관리**
- 이름은 앞뒤 공백을 빼고 1~20자다. 대소문자를 구분하지 않고 중복을 막는다.
- 행성은 최대 50개까지 만들 수 있다 (잠정).
- 삭제는 별이 0개인 행성만 할 수 있다. "0개"는 **전체 기간** 기준이다. 기간 밖에 별이 하나라도 있으면 지울 수 없다 (SPEC S4 확정).
- 합치기는 A를 B에 합치는 방식이다. A의 별이 모두 B로 옮겨지고 A는 삭제된다. 되돌릴 수 없으므로 확인창을 띄운다.

**2-5. 행성 크기 공식 (개발 C, 디자이너 1)**
- `반지름 = 기본값 × (1 + log2(1 + 기간 안의 별 개수))`
- 최소값은 기본값의 1배, 최대값은 기본값의 4배다. 별이 많은 행성 하나가 화면을 다 덮지 않게 하기 위해서다.
- 기간 안의 별이 0개인 행성은 그리지 않는다. 행성 목록에는 흐리게 표시한다.

**2-6. 입력 제한**
- 파일 1개는 최대 **200MB** (잠정)다.
- 한 번에 넣을 수 있는 파일은 최대 20개다. 파일마다 기록이 1개씩 생기고, 넣은 직후 확인에서 고른 행성과 메모는 모두에 같이 적용된다.
- 텍스트 기록은 최대 100,000자다. 더 길면 `.txt` 파일 기록으로 저장한다.
- 넣은 직후 메모는 한 줄, 최대 140자다. 웹에서 고치는 메모는 최대 1,000자다.
- 같은 파일(SHA-256이 같으면)은 다시 넣으면 새로 만들지 않고 "이미 [행성]에 있는 별이에요"라고 알려준다.

**2-7. 데이터 정제와 표기**

| 비어 있는 값 | 표기 |
| --- | --- |
| 링크 제목 | 도메인 (예: `youtube.com`) |
| 썸네일 | 유형별 기본 아이콘 |
| 파일 이름 | "이름 없는 기록" |
| 메모 | 화면과 내보내기에서 생략 |

- 날짜는 `YYYY.MM.DD HH:mm`으로 쓴다. 재발견에서는 "N일 전"으로 쓴다.

**2-8. 탐사선 내보내기 (개발 A)**
- 내보내기에는 종류, 행성, 넣은 날짜, 메모, 텍스트 본문, 링크 URL과 제목, 파일 이름이 들어간다.
- `.txt`, `.md` 파일은 본문을 파일당 최대 20,000자까지 넣는다. 다른 파일과 이미지는 이름과 종류만 넣는다.
- **절대 경로는 기본으로 넣지 않는다.** 경로에 사용자 이름이 들어가기 때문이다.
- 전체가 50,000자를 넘으면 "내용이 길어요"라고 경고하되, 복사는 막지 않는다.

**2-9. 삭제**
- 기록을 삭제하면 확인창을 띄운 뒤 보관함의 복사본까지 영구 삭제한다. 사용자의 원래 파일은 건드리지 않는다. MVP에는 휴지통이 없다.

## 3. 예외 상황 및 장애 대응 정책 (Edge Cases)

**3-1. 외부·서버 장애**

| 상황 | 대응 |
| --- | --- |
| 링크 정보를 못 가져옴 (시간 초과, 403, 429 등) | 기록은 저장한다. 제목은 도메인으로, 썸네일은 기본 아이콘으로 둔다. 다시 시도하지 않는다. |
| 웹이 로컬 서버에 연결하지 못함 | 화면을 멈추지 않는다. 마지막으로 받은 데이터를 유지하고 "수집 앱이 꺼져 있거나 응답하지 않아요" 배너와 [다시 시도] 버튼을 띄운다. |
| 로컬 서버가 갑자기 꺼짐 | 수집 앱이 1번 자동으로 다시 켠다. 다시 실패하면 트레이 아이콘에 오류 표시를 하고 알림을 띄운다. |
| 보관함에 접근할 수 없음 (외장 드라이브 분리, 권한 없음) | 저장을 막고 "보관함을 찾을 수 없어요"라고 알린 뒤 설정 화면으로 안내한다. |
| 디스크 남은 공간이 1GB 미만 | 드롭존에 경고를 띄운다. 넣을 파일보다 공간이 작으면 저장을 거부한다. |
| WebGL을 쓸 수 없음 | 3D 대신 행성 목록과 패널만 보여주고 "이 브라우저에서는 3D 우주를 볼 수 없어요"라고 알린다. |

**3-2. 데이터 0건**
- 오늘 0건이면 이번 주로 넓히고 "오늘은 별이 없어 이번 주 우주를 보여드려요"라고 알린다 (PRD에 정해진 동작).
- 이번 주도 0건이면 빈 우주에 "드롭존에 첫 별을 끌어다 놓아 보세요"를 띄운다.
- 전체 기록이 0건이면 첫 실행 안내(드롭존 위치, 단축키)를 보여준다.
- 행성 패널에 별이 0개면 "아직 이 행성에 별이 없어요"와 [행성 삭제] 버튼을 보여준다.
- 탐사선에 실은 것이 0개면 [복사하기]를 비활성화한다.

**3-3. 입력 경계값**

| 상황 | 대응 |
| --- | --- |
| 폴더를 끌어다 놓음 | 거부하고 "폴더는 아직 넣을 수 없어요. 파일을 넣어 주세요"라고 알린다. |
| 클립보드가 빈 채로 단축키를 누름 | "클립보드가 비어 있어요"라는 짧은 토스트를 띄운다. |
| 지원하지 않는 클립보드 형식 | 거부하고 형식 이름을 알려준다. |
| 200MB 초과, 21개 이상 | 넘은 파일만 거부하고 이유를 알려준다. 나머지는 저장한다. |

**3-4. 이상값 플래그**
- **원본 없음 ⚠**: 보관함에서 원본이 사라진 별은 기록을 유지한다. 별 상세에 "원본을 찾을 수 없어요"를 보여주고, [원본 열기] 버튼을 비활성화한다.
- **링크 정보 없음**: 도메인을 제목으로 쓰고 따로 경고하지 않는다.
- **성능 상한 (잠정)**: 기간 안의 별이 2,000개를 넘으면 별은 그리지 않고 행성과 별 개수만 보여준다. "기간을 좁히면 별이 보여요"라고 안내한다. 이 수치는 개발 C의 1주 차 측정으로 확정한다.
- **클립보드 쓰기 실패 (탐사선)**: 직접 선택해 복사할 수 있는 텍스트 상자로 보여준다.
- **PC 시계나 시간대가 바뀜**: 저장된 UTC를 기준으로 다시 계산한다. 미래 시각의 기록은 "오늘"에 넣는다.
